# Защита webhook от SSRF и подпись HMAC — сверх ТЗ

ТЗ не требует защищать `webhook_url`, но адрес приходит от клиента, и без
проверки сервис можно заставить стучаться во внутреннюю сеть (метаданные
облака, БД, админки). Поэтому хост резолвится и должен быть публичным, а
соединение идёт на проверенный IP. Тело webhook подписывается HMAC-SHA256 с
timestamp, чтобы получатель отличил настоящее уведомление от подделки.

## Considered Options

- **Без защиты**. Проще, но открытый SSRF в платёжном сервисе.
- **Проверка только при создании платежа**. Обходится DNS rebinding: адрес
  меняется между созданием и доставкой.
- **Проверка при создании и перед каждой отправкой, пиннинг IP** (выбрано).

## Consequences

Пиннинг IP требует клиента без keep-alive и без прокси из окружения (см.
`app/webhook.py`). Демо-приёмник внутри docker-сети пропускается через
`WEBHOOK_ALLOWED_HOSTS`.
