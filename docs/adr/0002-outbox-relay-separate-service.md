# Публикатор outbox — отдельный сервис

События из таблицы `outbox` публикует сервис `outbox-relay`, а не фоновая задача
в процессе `api`. Строки берутся `SELECT ... FOR UPDATE SKIP LOCKED`, поэтому
несколько реплик relay не опубликуют одно событие дважды.

## Considered Options

- **Фоновая задача в api**. Нет лишнего контейнера, но api начинает зависеть от
  RabbitMQ: брокер недоступен — не стартует и HTTP. Масштабирование api тянет за
  собой число публикаторов.
- **Публикация сразу после коммита + relay как страховка**. Быстрее в среднем,
  но два пути публикации — два места для ошибок.
- **Отдельный сервис** (выбрано). api зависит только от PostgreSQL, relay
  масштабируется и перезапускается независимо, корректно завершается по SIGTERM.

## Consequences

Сбой публикации одного события не откатывает пачку: строка получает `attempts`
и `last_error` и берётся снова. После `OUTBOX_MAX_ATTEMPTS` неудач событие уходит
в карантин и разбирается вручную. Опубликованные события старше
`OUTBOX_RETENTION_HOURS` relay удаляет сам.
